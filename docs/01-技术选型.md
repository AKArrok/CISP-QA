# 01 技术选型

> 结论：**不直接采用外部开源平台，自研轻量 RAG 流水线（LangGraph 编排）**；出题考核与薄弱点画像模块自研（无现成开源实现可直接复用）。

## 1. 需求回顾

做一个 CISP（注册信息安全专业人员）备考问答机器人：

1. **知识库问答**：基于本地课程资料（10 个知识域课件 + 知识点总结）回答用户问题，答案要能溯源到知识域。
2. **出题考核**：针对用户薄弱知识域出题（真题为主、AI 生成补充），判分并展示解析。
3. **薄弱点画像**：记录答题历史，按知识域统计正确率，反哺出题策略。

## 2. 候选方案对比

| 方案 | 问答能力 | 出题/刷题 | 薄弱点画像 | 实现成本 | 结论 |
|------|---------|-----------|-----------|---------|------|
| **自研轻量流水线**（本项目） | ✅ 按需实现：混合检索、RRF 融合、reranker、多轮对话、SSE 面板 | ❌ 自研 | ❌ 自研 | 中：检索/编排层代码量可控，无平台重依赖，全部代码自己掌握 | **采用** |
| Dify / MaxKB / FastGPT / RAGFlow | ✅ 平台化知识库问答开箱即用 | ❌ 无 | ❌ 无 | 高：平台重（Docker 全家桶），出题要按其工作流体系重写，定制受限 | 不采用 |
| QuizGenie / Skill-Anything 等出题类项目 | ❌ 仅"上传文档→生成测验"单一功能 | ✅ 有出题 | ⚠️ 仅间隔重复概念，无知识域画像 | 中：问答侧要从零补齐，且均为英文生态 | 不采用 |

调研来源：GitHub `quiz-generator` / `question-generator` topics、[开源 RAG 框架盘点](https://www.firecrawl.dev/blog/best-open-source-rag-frameworks)。所有出题类项目都止步于"文档→测验"，没有"真题库管理 + 知识域画像 + 问答"三合一的实现。

## 3. 自研模块与处理方式

| 模块 | 处理方式 |
|------|---------|
| `llms.py`（LLM 工厂、tenacity 指数退避重试、结构化输出 JSON 降级、Ark embedding 客户端） | **自研封装**，OpenAI 兼容协议层，不绑定具体向量库/搜索服务 |
| `config.py` | 环境变量驱动，仅保留 LLM + DashScope/Ark/本地 embedding 相关配置 |
| 分句分块算法 | 自研：课件 PDF 按页 + 语义分块（structured Child/Parent 策略） |
| LangGraph 编排、SessionStore、MemorySaver 多轮记忆 | 自研多阶段流水线：route → rewrite → retrieve → answer → persist（见 03 架构） |
| `server.py` FastAPI + SSE、`static/` 面板 | Web 层自研，问答/刷题双页签 |
| 联网搜索（Tavily 类）、外部元数据服务 | **不纳入**：答案只依据本地知识库 |

## 4. 已确认的关键决策

| 决策点 | 结论 |
|--------|------|
| LLM / Embedding | LLM 沿用 DeepSeek key（主答 + 轻量路由）。**Embedding 原计划沿用 Ark doubao-embedding-vision，但实施时发现 Coding Plan 订阅已失效**（2026-08-29 实测报 InvalidSubscription），已切换到本地 Qwen/Qwen3-Embedding-0.6B（1024 维，CPU 可跑，`EMBEDDING_BACKEND=local`）。后续若续订 Ark，改回 `.env` 的 `EMBEDDING_BACKEND=ark` 并删除 `data/vectors.npz` 重建索引即可 |
| 向量库 | **本地化**：语料仅数千块，用 numpy 矩阵余弦检索（持久化 npz），零额外服务依赖；不用 Pinecone |
| 联网搜索 | 砍掉 Tavily，答案只依据本地知识库 |
| 出题来源 | **真题库抽题为主**（700 题 PDF + 6 套 docx），AI 生成题为补充（仅当某知识域真题不足时） |
| 数据范围 | V4.2 课件 PDF + 10 份知识点总结 PDF + V4.1 pptx 课件 + 700 题 + 6 套真题 docx + CISP216.docx 全部纳入 |

## 5. 新增依赖

```
langchain-openai   # ChatOpenAI（OpenAI 兼容协议层）
pymupdf            # PDF 文本提取（课件、700题PDF）
python-docx        # 真题 docx 解析
python-pptx        # V4.1 pptx 课件解析
jieba              # BM25 中文分词
```

检索栈：dense（numpy 余弦）+ sparse（jieba BM25 自实现，语料小无需 Whoosh）→ RRF 融合。语料规模下毫秒级响应，无需 FAISS/Chroma 进程。
