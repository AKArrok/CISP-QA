# 07 - 模拟用户评测

没有真实用户时，用两类模拟暴露真实使用场景下的问题：**模拟用户"怎么问"**（问法鲁棒性）与**模拟用户"怎么用"**（刷题-画像-复习闭环验证）。两者的产物都是可回归的评测脚本，真实用户到来后可替换为真实数据。

## 1. 问法鲁棒性（模拟提问风格）

`tests/eval_query_robustness.py`：把 holdout 题用 LLM 改写成三种真实风格变体（口语随意 / 带错别字 / 极简省略，每域抽 3 题 × 3 风格 = 90 查询），在现网口径下检索并与规范问法对比。变体与检索结果全部落盘缓存。

### 1.1 首轮测量（发现短板）

| 问法 | Recall@1 | 相对规范问法 |
|------|----------|--------------|
| 规范问法 | 93.3% | — |
| 口语随意 | 90.0% | −3.3pp |
| **带错别字** | **80.0%** | **−13.3pp** |
| 极简省略 | 80.0% | −13.3pp |

错别字（"威胁**请报**很**重药**""**信西**安全管理对**组只**有什么**做用**"）主要打崩 BM25 词法匹配，但多数仍挂在 Top6-9。**问法风格带来的退化（−13pp）远大于精排融合的贡献（+2pp）**——真实用户场景的最大短板在词法鲁棒性。

### 1.2 修复：BM25 自适应混词通道（`retrieval/bm25.py`）

两个被证伪的方案先记录在案：整表混入 bigram token（标准问法 R1 −2pp，bigram 噪声稀释打分）、词级/bigram 双通道 RRF（标准问法 −3pp，typo 反而更差——泛化 bigram 让无关页排前）。最终定型**查询自适应**：

- 查询词全部在语料词表中（健康信号）→ 纯词级打分，排序零扰动；
- 查询含词表外词（错别字的特征信号）→ 切换"词 + 相邻 bigram"混词打分，部分匹配救回词法召回。

### 1.3 修复后

| 问法 | 修复前 | 修复后 |
|------|--------|--------|
| 规范问法（holdout 100 题） | 92.0% | **92.0%（零回归）** |
| 口语随意 | 90.0% | 90.0% |
| 带错别字 | 80.0% | **83.3%** |
| 极简省略 | 80.0% | **86.7%** |

## 2. 虚拟学生：画像/复习闭环验证

`tests/simulate_students.py`：造 3 个带"预设强弱域"的虚拟学生在真实题库（1267 题）上作答（sqlite 隔离，不碰真实数据），验证画像层核心逻辑：

| 校验项 | 结果 |
|--------|------|
| 场景 A：弱域被识别（支撑/软件开发 0.35-0.4）、强域不误报 | ✓ |
| 场景 A：Elo 评分与能力排序一致 | ✓ |
| 场景 A：薄弱强化选题权重显著偏向弱域（>1.5×） | ✓ |
| 场景 C：弱域（0.3）被识别、强域（0.9）不误报 | ✓ |
| FSRS：答错建卡短间隔到期 | ✓ |
| FSRS：连续答对间隔单调拉长 | ✓ |
| FSRS：到期队列按最久未复习优先 | ✓ |
| 场景 B：健康学生（0.75）无误报 | ✓（≤3 个误报属小样本噪声） |

### 模拟发现的两个真实问题（记录在案）

1. **薄弱域判定的小样本敏感**：12 题/域时 Beta 后验波动即产生 0-3 个误报，n≥2 的 insufficient 门槛偏激进。产品启示：真实用户前几十次答题的"薄弱域"标签应视为低置信，建议随答题量动态收紧（待真实数据校准）。
2. **同能力域 Elo 分差可达 300+**（全域 0.6 的学生各域 1402~1747）：题目难度未参与建模或 K 值偏大，Elo 只宜作排序信号（排序仍正确），不宜作绝对水平展示。

## 2.5 多轮追问：上下文连续性加成（负结果记录）

多轮追问基线 80%（8/10，指代消解改写 10/10 全对）。对其中一个 MISS（BIA 与 RTO 的关系页被 RPO 页压住）实现了**上下文连续性加成**（`rank_features.py`）：上一轮命中页的"翻页邻域"（同源 1≤|Δ页|≤3）在追问轮获得 +0.0015 加成，已读页本身（Δ=0）不加成，单轮不生效。链路：graph 的 retrieve 节点从 checkpointer 状态取上一轮 contexts 传入；检索缓存 key 含上下文指纹。

**结果：10 题集上无可测收益（BIA 题证据页仍在 R7，与前两名分差大于加成量级）**。教训有二：一是曾用无锚点的字符串替换调权重，误伤了 `_source_bonus`（0.0015→0.003），靠单测逐例归因才发现——改特征权重必须精确落点并回归；二是该 MISS 的本质是相邻概念排序分差超过邻域先验的合理量级，正确解法是 rerank 融合（额度恢复自动生效）而非加大启发式。加成机制保留（0.0015，单测覆盖），待真实多轮对话积累后再评估。

## 4. RAG-Fusion 式查询变体（多轮 80% → 100%）

邻域加成的负结果说明两个 MISS 不在"翻页邻域"层面。改从**查询多样性**入手（RAG-Fusion 模式）：改写节点在指代消解之外，额外生成 2 个检索变体——完整问句版（补全省略、**纠正错别字**）与关键词版，各路独立检索后 RRF 融合（原查询权重加倍，单查询路径零扰动）。实现：`agents/graph.py` rewrite 节点（首单轮也生成，顺带纠错）、`retrieval/hybrid.py` `_core_retrieval`/`_merge_pools`、缓存 key 含变体指纹。

| 指标 | 变体前 | 变体后 |
|------|--------|--------|
| 多轮追问命中率 | 80%（8/10） | **100%（10/10）**——BIA/RTO 与 SSE-CMM 两个 MISS 全部救回 |
| 单轮 holdout（直连路径，无变体） | 92.0% | 92.0%（零回归，符合设计） |
| typo 查询抽查（真实对话链路） | 3 题中 2 题在 Top6-9 | **3/3 Top5 HIT** |

变体生成器自发完成了 LLM 层纠错："威胁**请报**很**重药**"→"威胁情报为什么对信息安全很重要"——比 BM25 模糊匹配更根治。成本：每查询 +1 次 DeepSeek flash 变体生成 + 2 次 flash 向量（变体文本逐次生成，向量缓存命中率低，但量级可忽略）。

## 5. UI 浏览器实测 + 并发压测（前端修复 + 超时修复）

### UI 浏览器实测（浏览器自动化全流程）

问答页签：流式回答完整渲染、追问多轮正常、出处展示；刷题页签：出题/选项/判分/解析/关联课件按钮/薄弱画像全通；控制台零 JS 报错。发现并修复两个前端问题（`static/app.js`）：

1. **Markdown 原样显示**：聊天气泡用 `textContent` 拼接，`**加粗**`/`---`/列表按原文展示。修复：新增 `renderMarkdown()`（先转义 HTML 防注入，再做加粗/行内代码/列表/分隔线/换行的有限转换），流式期间增量重渲染。
2. **出处双行重复**：模型自带【出处】行 + 前端 contexts 渲染的来源行同时显示。修复：前端剥离模型出处行，统一由页面底部按实际检索页渲染。
3. 附带修复：`index.html` 给 app.js 引用加版本参数（`?v=2`）——无 Cache-Control 头时浏览器启发式缓存会长期滞留旧脚本。

### 并发压测（12 路问答 + 10 路刷题，变体机制上线后）

| 轮次 | 结果 | 尾部延迟 |
|------|------|----------|
| 第一轮 | 21/22（1 例 656s 超时） | 长期记忆 embedding 客户端无超时，挂起把 done 事件拖住 600s+ |
| 修复后（`EMBEDDING_CLIENT_TIMEOUT=30`） | **22/22** | p50 11.5s；尾部 502s 为 DeepSeek 服务端并发排队（无 429，客户端重试 8 次后成功） |

修复与结论：embedding 客户端加 30s 显式超时，挂起场景对 SSE done 事件的拖累从 600s+ 降到 30s；502s 尾部是 DeepSeek 服务端并发容量限制（单用户场景 1-2 路并发不受影响），若需支撑高并发可在应用层加 LLM 调用信号量排队。变体机制在 12 路并发下无失败。

```bash
python tests/eval_query_robustness.py            # 问法鲁棒性（变体已缓存，重复运行零消耗）
python tests/eval_query_robustness.py --regen    # 重新生成变体
python tests/simulate_students.py                # 虚拟学生闭环验证
```
