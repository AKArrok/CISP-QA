# 03 架构设计

## 1. 总体结构

```
CISP/
├── config.py              # 配置（裁剪自 AniRAG：LLM + DashScope/Ark/本地 embedding，无 Pinecone/Tavily）
├── llms.py                # 移植自 AniRAG：LLM 工厂 / 重试 / 结构化输出降级 / Embedding 客户端
├── data_ingest/
│   ├── parse_courses.py   # 课件 PDF / PPTX → data/kb_chunks.json
│   ├── parse_questions.py # 真题 PDF / docx → data/questions.json (+ parse_failures.json)
│   ├── build_index.py     # kb_chunks → embedding → data/vectors.npz（断点续跑）
│   └── manifest.py        # 数据资产版本清单（启动自检，防解析/索引错配）
├── retrieval/
│   ├── vector_store.py    # 本地向量库：numpy 余弦，npz 持久化
│   ├── bm25.py            # jieba 分词 BM25
│   ├── reranker.py        # bge-reranker-v2-m3 交叉编码精排（失败优雅降级）
│   └── hybrid.py          # dense + sparse → RRF → 域过滤 → 精排 → top-k
├── agents/
│   ├── graph.py           # LangGraph: route → rewrite → retrieve → answer → persist
│   ├── state.py           # AgentState（含 usage Token 用量）
│   ├── prompts.py         # CISP 教材风格 system prompt（禁编造、带出处）
│   ├── memory.py          # 长期记忆：对话轮次落盘 SQLite conversations 表
│   ├── metrics.py         # 可观测性：请求级耗时/Token 用量落盘 metrics 表
│   └── session.py         # SessionStore（移植 AniRAG 模式：MemorySaver + thread_id）
├── quiz/
│   ├── store.py           # SQLite：questions 快照 + attempts 答题记录
│   ├── selector.py        # 抽题：随机 / 薄弱加权（Elo 缺口 + 复习到期）
│   ├── generator.py       # AI 补充出题：检索知识块 → LLM 生成单选（含解析）
│   ├── grader.py          # 判分 + 解析组装（关联知识块原文）
│   └── stats.py           # 掌握度画像：Beta 后验置信度 / Elo 评级 / 遗忘曲线
├── server.py              # FastAPI：/chat/stream SSE + /quiz/* + /api/stats + /api/metrics + 静态面板
├── static/                # 双页签 UI：问答 / 刷题（含统计卡片）
├── tests/                 # fixtures 单测、检索/意图评测、判分与记忆单测
└── docs/
```

## 2. 数据流

### 2.1 入库（离线，一次性）

```
课件 PDF/PPTX ──按页提取──► chunk{domain, source, page, text} ──► kb_chunks.json
700题PDF/docx ──正则+结构解析──► question{stem, options, answer, analysis, domain, source} ──► questions.json
kb_chunks ──qwen3.7-text-embedding（DashScope/百炼）──► vectors.npz（向量矩阵 + chunk 元数据）+ BM25 倒排（内存构建）
```

- 默认分块策略为 `structured_v1`：先清理文档内重复页眉、页脚和页码，再按标题、项目符号、段落生成约 220 字、最大 420 字的语义 Child；Child 用于 Dense/BM25/精排，命中后返回完整页面 Parent 给回答模型。相邻 Child 重叠一个语义单元，使用内容哈希生成稳定 ID，并对跨版本规范化重复块去重。`--strategy legacy` 保留旧的按页切片用于 A/B。
- 题目解析规则：`题干 → A./B./C./D. 选项 → 答案：X → 解析：...`，多套 docx 格式不同，解析器按格式探测 + 兜底正则；解析失败逐题落 `parse_failures.json`。
- 知识域打标：文件名即知识域（课件）；真题按"题型目录/章节"关键字映射 + LLM 兜底分类。

### 2.2 问答（在线）

```
用户问题 ─► route（轻量 LLM：闲聊 / 知识问答 / 想做题）
  ├─ 闲聊 ─► 直接回答（不检索）
  ├─ 想做题 ─► 引导到刷题页签（返回提示文案）
  └─ 知识问答 ─► 追问改写（结合历史，指代消解）
        ─► hybrid retrieve（dense top20 + BM25 top20 → RRF → top5）
        ─► answer（主 LLM，流式；system prompt 强制"只依据资料，答不出就说未覆盖，末尾列出处"）
```

与 AniRAG 的差异：砍掉 Expert 并行/评估重规划/别名/联网，保留"路由 → 检索 → 流式回答"主线 + 追问改写。CISP 问答以单点事实为主，复杂编排收益低、延迟成本高。

### 2.3 刷题（在线）

```
POST /quiz/next {mode: random|weak, domain?}
  ─► selector：random=均匀抽未做过的真题；weak=按域 掌握度加权抽域再抽题
  ─► 真题不足时 generator：检索该域知识块 → LLM 生成单选题（AI 生成标记 + 落库去重）
  ─► 返回脱敏题目（不含答案）
POST /quiz/answer {question_id, choice}
  ─► grader：判分 → SQLite 落 attempts → 返回对错 + 解析 + 关联知识块原文
GET /api/stats ─► stats：每域 {mastery, confidence, rating, last_seen_days, weak, due_for_review}
```

## 3. 关键设计决策

| 决策 | 理由 |
|------|------|
| 本地向量库用 numpy 矩阵而非 FAISS/Chroma | 语料约 2k–4k 块，全量内存余弦 < 10ms，npz 持久化即可；省去原生依赖在 Win/Py3.13 的安装风险 |
| BM25 自实现（jieba 分词） | 语料小，Whoosh 已停更且 py3.13 兼容性差；100 行内可实现 IDF+BM25 |
| 判题走确定性代码而非 LLM | 选项比对是精确匹配，无需 LLM，保证判分零误差 |
| AI 生成题先落库再出题 | 避免同题重复生成，题库可审计 |
| 真题答案为空/解析缺失的题 | 保留但标记 `needs_review`，出题时跳过 |

## 4. 记忆设计

| 层 | 机制 | 生命周期 |
|----|------|---------|
| 短期（对话内） | LangGraph `MemorySaver` checkpointer，`add_messages` 累积消息；`rewrite` 节点取最近 4 条做指代消解 | 进程内，重启即清 |
| 长期（跨会话） | 图末尾 `persist` 节点把每轮（用户问题 + 回答 + 意图）写入 SQLite `conversations` 表（`agents/memory.py`），提供 `load_history` / `list_threads` 与 `GET /api/history`、`GET /api/threads` | 磁盘持久，重启不丢 |
| 长期（学习画像） | SQLite `attempts` 表实时聚合 → **Beta 后验掌握度**（`Beta(对+1, 错+1)` 均值即掌握度，`P(能力<0.6)` 判薄弱）+ **Elo 评级**（按时间 replay，`rating` 增量更新）+ **遗忘曲线**（`2^(-天数/半衰期)`，到期进复习队列）→ weak 出题加权（Elo 缺口 + 薄弱 + 复习加成） | 磁盘持久 |

对话落盘只做记录与查询（会话恢复入口），不自动回灌进上下文——备考场景历史轮次价值有限，回灌收益待评测后再开。

## 5. 配置与环境

`.env`（沿用 AniRAG 的 key）：`LLM_API_KEY / LLM_BASE_URL / LLM_MODEL / SIMPLE_LLM_MODEL` + embedding 配置。**Embedding 当前为 DashScope/百炼模式**（`EMBEDDING_BACKEND=dashscope`，`qwen3.7-text-embedding` / 1024 维）；`local`（Qwen3-Embedding-0.6B，经 hf-mirror 下载）与 `ark`（Coding Plan）为可选后端。校验函数只要求 LLM 的 key（Pinecone/Tavily 已移除）。

## 6. 测试策略

| 层 | 用例 |
|----|------|
| 解析自检 | 题库条数符合预期；每题字段完整性（题干/≥2 选项/答案 ∈ ABCD…）；`parse_failures.json` 审阅 |
| 检索评测 | 20 条样例问题（覆盖 10 域）人工核对 top5 是否命中正确知识域，目标 ≥ 15/20 |
| 判分单测 | 单选/多选/错答/重复作答的 grader 行为 |
| 端到端 | 启动 server，问答一轮 + 刷题一轮（random 模式）走通 |

## 7. 风险与应对

| 风险 | 应对 |
|------|------|
| 真题 PDF/ docx 格式不统一，解析率低 | 解析器做格式探测 + 逐题容错，失败题落文件人工补 |
| Ark embedding 限流拖慢建库 | 移植 AniRAG 的限流退避 + 断点续跑（按 chunk 序号增量） |
| 课件 PDF 含扫描页（提取为空） | 检测空页记录警告，跳过；该部分知识由知识点总结 PDF 兜底 |
| LLM 答案幻觉 | prompt 强制"仅依据资料"，检索为空直接拒答 |
