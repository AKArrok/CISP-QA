# 03 架构设计

## 1. 总体结构

```
CISP/
├── config.py              # 配置（环境变量驱动：LLM + DashScope/Ark/本地 embedding）
├── llms.py                # LLM 工厂 / 重试 / 结构化输出降级 / Embedding 客户端
├── data_ingest/
│   ├── parse_courses.py   # 课件 PDF / PPTX → data/kb_chunks.json
│   ├── parse_questions.py # 真题 PDF / docx → data/questions.json (+ parse_failures.json)
│   ├── build_index.py     # kb_chunks → embedding → data/vectors.npz（断点续跑）
│   └── manifest.py        # 数据资产版本清单（启动自检，防解析/索引错配）
├── retrieval/
│   ├── vector_store.py    # 本地向量库：numpy 余弦，npz 持久化
│   ├── bm25.py            # jieba 分词 BM25
│   ├── reranker.py        # bge-reranker-v2-m3 交叉编码精排（失败优雅降级）
│   └── hybrid.py          # dense + sparse → RRF → 域过滤 → 精排 → top-k
├── agents/
│   ├── graph.py           # LangGraph: route → rewrite → retrieve → answer → persist
│   ├── state.py           # AgentState（含 usage Token 用量）
│   ├── prompts.py         # CISP 教材风格 system prompt（禁编造、带出处）
│   ├── memory.py          # 短期上下文缓存 + 长期向量记忆
│   ├── metrics.py         # 可观测性：请求级耗时/Token 用量落盘 metrics 表
│   └── session.py         # SessionStore（MemorySaver + thread_id，thread 间隔离）
├── quiz/
│   ├── store.py           # SQLite：questions 快照 + attempts 答题记录
│   ├── selector.py        # 抽题：随机 / 薄弱加权（Elo 缺口 + 复习到期 + 提问信号）
│   ├── generator.py       # AI 出题：错题锚点定向 / 域内补题 → 结构校验 → 近似查重 → LLM 自校验
│   ├── grader.py          # 判分 + 解析组装 + FSRS 复习卡更新
│   ├── review.py          # 题目级 FSRS 复习调度（py-fsrs：答错=Again、答对=Good）
│   └── stats.py           # 掌握度画像：Beta 后验 / Elo / 遗忘曲线 + 提问信号融合
├── server.py              # FastAPI：/chat/stream SSE + /quiz/* + /api/stats + /api/metrics + 静态面板
├── static/                # 双页签 UI：问答 / 刷题（含统计卡片）
├── tests/                 # fixtures 单测、检索/意图评测、判分与记忆单测
└── docs/
```

## 2. 数据流

### 2.1 入库（离线，一次性）

```
课件 PDF/PPTX ──按页提取──► chunk{domain, source, page, text} ──► kb_chunks.json
700题PDF/docx ──正则+结构解析──► question{stem, options, answer, analysis, domain, source} ──► questions.json
kb_chunks ──qwen3.7-text-embedding（DashScope/百炼）──► vectors.npz（向量矩阵 + chunk 元数据）+ BM25 倒排（内存构建）
```

- 默认分块策略为 `structured_v1`：先清理文档内重复页眉、页脚和页码，再按标题、项目符号、段落生成约 220 字、最大 420 字的语义 Child；Child 用于 Dense/BM25/精排，命中后返回完整页面 Parent 给回答模型。相邻 Child 重叠一个语义单元，使用内容哈希生成稳定 ID，并对跨版本规范化重复块去重。`--strategy legacy` 保留旧的按页切片用于 A/B。
- 表格感知切片（`data_ingest/tables.py`，`structured` 策略默认开启，`ENABLE_TABLE_CHUNKING=false` 可关）：`pymupdf find_tables` 检测到的合格表格序列化为 markdown，生成独立的表格 Child，并把表格正上方最近的正文块作为表题/引导语注入 Child 文本——表格单元格脱离页面语境后几乎不可检索，表题就是它的语义锚点。质量过滤（非空格数≥8、列数≤10、总格数≤100、密度或列数豁免、bbox 区域字符保真度≥0.75）用于剔除版式装饰框/并排多表误检；未通过过滤的"表格"保持平铺留在正文，避免抽取丢字。表格页的 Parent = 正文 + markdown 表格，表格 Child 与正文 Child 共享同一 parent_id：召回任一侧，回答时"正文+表格"完整上下文一起送给 LLM。超长表格按数据行切分并重复表头行，保证行仍能对上列名。
- 题目解析规则：`题干 → A./B./C./D. 选项 → 答案：X → 解析：...`，多套 docx 格式不同，解析器按格式探测 + 兜底正则；解析失败逐题落 `parse_failures.json`。
- 知识域打标：文件名即知识域（课件）；真题按"题型目录/章节"关键字映射 + LLM 兜底分类。

### 2.2 问答（在线）

```
用户问题 ─► route（轻量 LLM：闲聊 / 知识问答 / 想做题）
  ├─ 闲聊 ─► 直接回答（不检索）
  ├─ 想做题 ─► 引导到刷题页签（返回提示文案）
  └─ 知识问答 ─► 追问改写（结合历史，指代消解）
        ─► hybrid retrieve（dense top20 + BM25 top20 → RRF → top5，每块附带 dense 余弦分）
        ─► 相关性门限（ENABLE_RELEVANCE_GATE，RELEVANCE_FLOOR=0.45）：最高 dense 余弦
            低于门限 → 直接返回拒答话术，跳过回答 LLM；无 dense_score 的结果保守放行
        ─► answer（主 LLM，流式；system prompt 强制"只依据资料，答不出就说未覆盖，
            通用补充须标注，末尾列出处"）
```

拒答是双层的：门限在 LLM 之前拦"明显离题"（校准：gold 正常问题最低约 0.60，离题集最高约 0.41，门限 0.45 居中），回答 prompt 规则 1 兜"域内但课件未覆盖"（此时检索分通常不低，靠 LLM 判定资料不足并给出标注过的通用补充）。

编排刻意保持单线流水线：不引入 Expert 并行/评估重规划等复杂编排，保留"路由 → 检索 → 流式回答"主线 + 追问改写。CISP 问答以单点事实为主，复杂编排收益低、延迟成本高。

### 2.3 刷题（在线）

```
POST /quiz/next {mode: random|weak, domain?, anchor_question_id?}
  ─► selector：random=均匀抽未做过的真题；weak=FSRS 到期复习卡优先，
      无到期卡再按域 掌握度加权抽域再抽题（Elo 缺口 + 薄弱 + 复习到期 + 提问信号加成）
  ─► 真题不足时 generator：检索该域知识块 → LLM 生成单选题 → 结构校验（答案合法/
      选项互异）→ 近似查重（前缀 + 同域相似度）→ LLM 自校验（不过标 needs_review 留档）
  ─► anchor_question_id 指定锚点题时：以"用户刚答错的题"为检索与命题依据，
      围绕同一考点的易混淆概念定向生成同类题
  ─► 返回脱敏题目（不含答案）
POST /quiz/answer {question_id, choice}
  ─► grader：判分 → SQLite 落 attempts + FSRS 复习卡（答错=Again、答对=Good）
      → 返回对错 + 解析 + 关联知识块原文（前端提供"去问答深挖/再练一道同类题"）
GET /api/stats ─► stats：每域 {mastery, confidence, rating, last_seen_days, weak,
      due_for_review, asks, ask_unverified} + 全局 review_due_cards
```

提问信号：问答 route 节点顺带判定问题所属知识域，`persist` 写入 `question_signals`
表并失效统计缓存。反复提问但答题样本不足的域标 `ask_unverified`，在 weak 抽题
加权中抬到不低于无记录域基线再乘 `ASK_WEIGHT_BONUS`——"哪里不会问哪里"先于
答题数据生效。

## 3. 关键设计决策

| 决策 | 理由 |
|------|------|
| 本地向量库用 numpy 矩阵而非 FAISS/Chroma | 语料约 2k–4k 块，全量内存余弦 < 10ms，npz 持久化即可；省去原生依赖在 Win/Py3.13 的安装风险 |
| BM25 自实现（jieba 分词） | 语料小，Whoosh 已停更且 py3.13 兼容性差；100 行内可实现 IDF+BM25 |
| 判题走确定性代码而非 LLM | 选项比对是精确匹配，无需 LLM，保证判分零误差 |
| AI 生成题先落库再出题 | 避免同题重复生成，题库可审计 |
| 真题答案为空/解析缺失的题 | 保留但标记 `needs_review`，出题时跳过 |

## 4. 记忆设计

| 层 | 机制 | 生命周期 |
|----|------|---------|
| 短期（对话内） | LangGraph `MemorySaver` checkpointer 保存当前进程上下文；每轮结束后同步把最近 `MEMORY_MAX_ROUNDS` 轮写入 `storage.cache`，Redis 可用时跨进程共享，不可用时降级进程内存；新图实例为空时从该缓存恢复上下文 | Redis TTL / 进程内 TTL，默认 `SHORT_MEMORY_TTL=7200` 秒 |
| 长期（跨会话） | 图末尾 `persist` 节点把每轮（用户问题 + 回答 + 意图）embedding 后追加到 `data/memory_vectors.npz`，原文/时间/意图写入 `data/memory_vectors.npz.meta.json`；回答前按当前问题从同 thread 语义召回 `LONG_MEMORY_TOP_K` 条 | 磁盘持久，重启不丢 |
| 长期（学习画像） | SQLite `attempts` 表实时聚合 → **Beta 后验掌握度**（`Beta(对+1, 错+1)` 均值即掌握度，`P(能力<0.6)` 判薄弱）+ **Elo 评级**（按时间 replay，`rating` 增量更新）+ **域级遗忘曲线**（`2^(-天数/半衰期)`，展示用）+ **题目级 FSRS 复习卡**（py-fsrs DSR 模型，每题独立 D/S/R 状态，weak 抽题时到期卡优先）+ **提问信号**（`question_signals` 表，问答 route 判域、persist 落库，高频提问未验证的域抽题加权） | 磁盘持久 |

`GET /api/history` 与 `GET /api/threads` 从长期向量记忆元数据恢复展示；长期向量记忆只辅助延续偏好和已讨论背景，不能替代课件证据。

## 5. 配置与环境

`.env` 关键 key：`LLM_API_KEY / LLM_BASE_URL / LLM_MODEL / SIMPLE_LLM_MODEL` + embedding 配置。**Embedding 当前为 DashScope/百炼模式**（`EMBEDDING_BACKEND=dashscope`，`qwen3.7-text-embedding` / 1024 维）；`local`（Qwen3-Embedding-0.6B，经 hf-mirror 下载）与 `ark`（Coding Plan）为可选后端。校验函数只要求 LLM 的 key（Pinecone/Tavily 已移除）。

## 6. 测试策略

| 层 | 用例 |
|----|------|
| 解析自检 | 题库条数符合预期；每题字段完整性（题干/≥2 选项/答案 ∈ ABCD…）；`parse_failures.json` 审阅 |
| 检索 smoke | 20 条样例问题（覆盖 10 域）人工核对 top5 是否命中正确知识域，用于粗粒度回归 |
| 知识点级检索评测 | 80 条 gold case（10 域各 8 题），按 `source + page + must_contain` 验证 Recall@K/MRR/nDCG，详见 `docs/05-检索测试集评测.md` |
| 判分单测 | 单选/多选/错答/重复作答的 grader 行为 |
| 端到端 | 启动 server，问答一轮 + 刷题一轮（random 模式）走通 |

## 7. 风险与应对

| 风险 | 应对 |
|------|------|
| 真题 PDF/ docx 格式不统一，解析率低 | 解析器做格式探测 + 逐题容错，失败题落文件人工补 |
| Ark embedding 限流拖慢建库 | embedding 客户端内置限流退避 + 断点续跑（按 chunk 序号增量） |
| 课件 PDF 含扫描页（提取为空） | 检测空页记录警告，跳过；该部分知识由知识点总结 PDF 兜底 |
| LLM 答案幻觉 | prompt 强制"仅依据资料"，检索为空直接拒答 |
